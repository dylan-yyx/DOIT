# DOIT 拾序

一个本地优先的 Windows 个人管理桌面软件。当前已实现待办、打卡、记账和投资资产模块初版。

## 直接使用

**下载 Windows 安装包：**打开 [最新版本下载页](https://github.com/dylan-yyx/DOIT/releases/latest)，在 Assets 中下载 `DOIT-Setup-0.3.3-x64.exe`，双击并按向导安装。安装后可从桌面或开始菜单打开 **DOIT 拾序**。无需安装 Node.js、Python 或其他开发工具，也无需登录账号。

安装版数据存放在 `%APPDATA%\DOIT\data\data.json`。升级或卸载程序保留数据，仍建议定期在“设置 → 数据管理”中导出备份。当前安装包未进行代码签名，Windows 可能显示“未知发布者”；下载页同时提供 `SHA256SUMS.txt` 供核对文件。

**本地便携版：**开发项目中的用户可继续双击 **启动DOIT.cmd**，或打开 `release/DOIT-win32-x64/DOIT.exe`。请保留同目录的其他文件；便携版数据位于软件旁的 `data/data.json`，移动软件时请一起移动整个文件夹。已有便携版数据可通过导出、导入转入安装版。

待办和习惯在首次启动时附有示例，可直接编辑或删除；记账和投资台账从空白开始。发布安装包不包含开发者的个人记录、背景图片或账号信息。

## 待办功能

- 事项必须属于一个清单；清单可以独立存在，也可以放入一个文件夹。清单与文件夹均可设置名称、图标和颜色。
- 标签独立于清单，一个事项可以使用多个标签。点击侧边栏标签可查看不同清单中相关的事项。
- 普通事项支持日期、全天、具体时间点、同日时间段、优先级、文字备注、检查事项。全部检查事项勾选后自动完成，取消一个勾选会重新打开事项。
- 备注支持直接输入 `#标签`：新建事项保存时，或在右侧详情离开备注输入区时，会转为事项标签并复用同名标签。普通说明文字会保留，URL 锚点、Markdown 标题和 `C#` 不会误识别。
- 右侧详情中的备注可直接点击空白输入并自动保存。标题右侧的检查事项图标可直接开启新增，Enter 连续添加；已有检查事项可直接改名、删除，新增未完成项会重新打开当前事项或本次重复记录。
- 重复方式支持每天、每周工作日、每周休息日、每周、每月、每年和自定义星期，可设置重复截止日期。每个日期独立记录完成状态及检查事项。
- 进度事项支持总目标、单位、起止日期和逐次进度记录。根据包含首尾日期的总天数，计算平均每天应完成的量，并显示截至当天的实际进度与累计计划进度。
- 支持列表、周视图、月视图，以及我的一天、最近七天、全部事项、收集箱、已完成、清单和标签筛选。
- 支持全局搜索事项名称、备注、检查事项和标签，以及按计划时间、优先级、创建时间排序。
- 自动保存到本机；设置中可导出完整 JSON 备份、预览并确认导入。删除事项后可在提示中撤销。删除清单会把事项移至收集箱，删除文件夹保留其清单。

进度示例：20 章分 5 天完成，平均每天 4 章。第一天记录 3 章时显示“比计划少 1 章”，第二天的累计计划量为 8 章。进度记录可以填写历史日期，或删除误记记录进行修正；累计达到目标后自动完成。

**日期规则：**周一为每周第一天；工作日指周一至周五，休息日指周六和周日，暂不联动法定节假日或调休。每月 31 日的重复任务在没有 31 日的月份落到月末；每年 2 月 29 日在非闰年落到 2 月 28 日。普通事项的时间段目前限定在同一天内。

## 打卡功能（初版）

- 习惯卡片、最近一周日期切换、分组筛选、搜索，以及最近 28 天打卡总览。
- 阅读、运动、喝水、戒糖、冥想、早睡、写作和外语学习预设，可在创建前调整；也可完全自定义。
- 每个习惯支持名称、频率、开始日期、分组和目标。频率可选每天、工作日、休息日或指定星期；分组支持创建时自定义。
- “完成即打卡”适合戒糖、早睡等习惯；“记录数值”支持目标和单位，记录当天累计总量，再次保存会覆盖原值。
- 以阅读 30 分钟为例，15 分钟会保留为未达标记录，30、60、90 分钟分别显示不同深浅的颜色。颜色表示相对于该习惯目标的完成强度。
- 右侧月历可查看与补记过去的计划日；未来日期、开始前与非计划日不能打卡。支持撤销打卡、编辑习惯和删除后撤销。
- 连续达标跳过非计划日；月完成率只计算截至今天的计划日。首次进入附有明确标注的示例习惯与记录，可编辑或删除。
- 习惯与待办共用本机保存和 JSON 备份；兼容旧版仅有待办的 v1 备份。

## 记账功能（初版）

- 收入、支出、日期、账户、分类与备注；支持查看、修改、删除和删除后撤销。
- 预置支付宝、微信、银行卡、现金，支持添加账户、改名、设置初始余额；账户余额按实际付款和到账金额计算。
- 预置饮食、交通、购物、居住、休闲娱乐、医疗健康、学习成长等支出分类，以及工资、奖金、兼职等收入分类；可添加和编辑分类、图标和颜色。
- 时间轴按天展示；月历展示每天的个人支出、收入、AA 回款与对账调整，点击日期可查看或补记账目。支持切换月份、账户/收支/分类筛选、名称与备注搜索。
- 月度统计展示个人支出、日常收入和收支结余，右侧展示支出去向及全部日期的 AA 待收款。统计随月份、账户、收支类型、分类及搜索变化；上方月统计不受日历选中日期影响。
- **AA 均摊：**例如四人聚餐代付 400 元，选择 4 人均摊后，付款账户减少 400 元，个人支出只计 100 元，应收他人 300 元。可以修改自己的承担金额，也可以分次、跨账户记录回款。回款按到账日期展示并增加收款账户余额，不计入收入；跨月回款也不会重复计入消费。均分不能整除时，个人承担向下取整到分，剩余部分归入他人应还，也可手动调整。
- **对账调整：**输入账户当日实际余额，系统按当日账面余额计算差额，支持正负调整。余额宝收益、小红包等可合并记录；调整单独展示，不计入日常收入、消费或收支结余。历史调整按当时保存的差额保留，修改旧流水后可再次对账。
- 金额以整数分保存，避免小数累计误差。账目从空账本开始，不生成示例交易；支持旧版数据自动补齐记账结构，所有账目、账户、分类及 AA 回款共用本机自动保存和完整 JSON 备份。

开始使用时，先在“管理账户”中填写**记账开始前的余额**，再记录收支。如果只想从当前余额开始，可以直接设置初始余额。

## 资产功能（初版）

- 投资总览、全部持仓、投资记录；支持按投资类型、持有平台及名称、代码、备注搜索。记录可按类型与月份筛选；持仓可查看正在持有、已清仓或全部产品。
- 基金、股票 / ETF、银行理财、债券、黄金和其他投资；同一产品在不同平台可分别建档。现金、银行卡余额及证券账户可用资金不计入投资市值。
- 按份额和单价管理，或按金额管理；已有持仓可直接填写期初成本、份额及价格 / 市值，无需补齐全部历史交易。也可先建产品，再录入第一笔买入。
- 支持买入、卖出、现金分红、分红再投、其他费用与单项 / 批量估值；每项持仓显示最近估值日期，以及期初、成交参考或手动估值来源。暂不获取自动行情，不改变记账账户余额。
- 份额模式采用移动平均成本核算部分卖出，全部卖出时结转全部剩余成本；金额模式的部分赎回需填写对应持仓成本和赎回后剩余市值，全额赎回可一键填写成本与零市值。
- 投资市值、当前持仓成本、累计收益及收益构成、分类持仓占比；累计收益包含持仓盈亏、已实现盈亏与现金 / 再投分红。分红再投同时增加持仓成本，避免重复统计；买入手续费计入成本，卖出与分红费用从到账额扣除，其他费用单独扣减收益。
- 已清仓产品保留全部历史和收益，也可重新买入；清仓后到账的现金分红仍可记录。投资总览统计随类型、平台和搜索变化，累计收益包含筛选范围内已清仓产品的收益，不受持仓状态或记录月份影响。
- 支持修改产品和历史记录、删除记录 / 产品及撤销；修改历史时会重算完整交易顺序，拒绝会造成后续超卖或成本不足的修改。同一天按录入顺序核算，编辑记录保留原有顺序。
- 金额以整数分保存，份额和价格最多六位小数；采用整数运算计算成交金额与成本分摊。投资从空台账开始，与其他模块共用自动保存、完整 JSON 备份、导入预览和旧版数据迁移。

**收益口径：**累计收益 = 当前市值 − 当前持仓成本 + 已实现盈亏（含其他费用）+ 现金分红净额 + 分红再投总额。期初成本直接包含历史费用；录入之前已卖出的收益与已领取分红不会自动追溯。追加投入和卖出回款不会直接记成收益。界面的持仓盈亏率仅针对当前持仓成本，不作为包含多次现金流的累计收益率。

## 外观设置

点击左下角“设置与数据”打开左右分栏的设置窗口。左侧“外观”用于切换背景与界面字体，选择后即时生效并自动保存；“数据管理”集中展示各模块记录数量、完整备份导入导出、数据位置与保存状态。

- 纯色背景：鼠尾草、云朵白、燕麦米、雾霭蓝、蔷薇粉和浅藤紫，四个模块共用主题。
- 图片背景：内置“远山”背景，也可上传本机 JPG、PNG 或 WebP 图片（最大 20 MB）。图片会自动缩放压缩并保存到本地数据中，移动或删除原图片不影响背景；支持更换、移除图片。
- 字体：系统默认、微软雅黑、宋体、楷体和霞鹜975圆体，使用电脑本地字体，缺少时使用备用字体。霞鹜975圆体支持本机安装的 SC 500W 版本。
- 外观偏好和自定义图片包含在完整 JSON 备份中，重启后自动恢复；旧备份仍可正常导入。“恢复默认”切回鼠尾草与系统字体，保留已上传的图片供再次选择。

## 开发

技术栈为 Electron + React + TypeScript + Vite。建议使用 Node.js 24 LTS，依赖版本记录在 `pnpm-lock.yaml`。

```powershell
pnpm install
pnpm build
pnpm start
```

开发时，先在一个终端运行 `pnpm dev`，再在另一个终端运行：

```powershell
$env:DOIT_DEV_URL = 'http://127.0.0.1:5173'
pnpm start
```

浏览器预览可访问 Vite 提供的本机地址，此时数据单独保存到浏览器的 localStorage。桌面开发版数据位于 `.local-data`，便携版位于软件旁的 `data`，安装版位于 `%APPDATA%\DOIT\data`，各自独立。

```powershell
pnpm test        # 日期、重复、完成、进度和备份验证的单元测试
pnpm build
pnpm test:e2e    # 实际启动 Electron，使用隔离的 .test-data 目录
pnpm test:inline # 备注标签、详情直接编辑、检查事项与重启恢复验证
pnpm test:habits # 习惯预设、自定义、目标强度、补记与重启保存验证
pnpm test:finance # 收支、账户、AA、对账、视图、备份和重启验证
pnpm test:assets # 投资持仓、成本收益、历史校验、估值、备份和重启验证
pnpm test:appearance # 背景、字体、图片上传、备份和重启恢复验证
pnpm package    # 生成 release/DOIT-win32-x64/DOIT.exe
pnpm package:installer # 在 pnpm package 后生成 Windows 安装包与 SHA-256 校验文件
```

端到端测试覆盖真实的界面操作、文件保存与重启恢复；备份测试仅替换系统文件选择框的返回路径，实际读写仍经过原生 IPC 和文件系统。截图保存在 `test-results`。

## 代码结构与扩展

```text
electron/
  main.cjs                 原生窗口、文件保存、备份对话框、IPC 边界
  preload.cjs              向界面提供有限的桌面 API
src/
  core/
    types.ts               数据类型与版本
    dates.ts               本地日期及日历运算
    seed.ts                首次启动的示例数据
    storage.ts             桌面文件存储 / 浏览器存储适配
  components/              图标、弹窗、侧边栏、清单/文件夹/标签编辑器
  modules/
    registry.ts            模块注册表
    tasks/
      logic.ts             重复规则、完成状态、进度计算、备份校验
      logic.test.ts        核心业务逻辑测试
      TaskEditor.tsx       事项编辑器
      TaskListView.tsx     列表与快速添加
      TaskDetail.tsx       详情、检查事项和进度记录
      CalendarView.tsx     周历与月历
    habits/                习惯、打卡和强度总览
    finance/
      logic.ts             整数分金额、实际余额、个人消费、AA 回款与校验
      FinanceBoard.tsx     时间轴、月历、筛选、月统计及账目详情
      FinanceEditor.tsx    收支、AA 与对账调整表单
      FinanceManagers.tsx  账户、分类及回款管理
    assets/
      logic.ts             份额精度、移动平均成本、分红及完整历史校验
      AssetBoard.tsx       总览、持仓、分类占比、记录与详情
      AssetEditors.tsx     产品、期初、买卖分红及批量估值表单
  App.tsx                  应用布局、模块切换和状态协调
  styles.css               统一配色、组件样式和窗口适配
scripts/                   桌面测试、图标生成和打包
```

增加新模块时，在 `src/modules/` 下创建对应模块，更新 `registry.ts`，并在 `App.tsx` 接入其页面。模块共用原生窗口、导航和数据备份设施；新增数据类型时应更新 `AppData`、备份校验和数据版本迁移逻辑。

当前采用版本为 1 的 JSON 数据格式，适合第一版个人单机使用。每次保存先写临时文件，再替换正式文件，`data.json.bak` 保留上一次保存的内容。软件不会自动读取损坏数据并覆盖为空白数据，读取或校验失败时会提示从备份恢复。

打包脚本在临时目录生成程序后合并到发布目录，保留已有的 `data` 文件夹。请在重新打包前退出运行中的软件，并定期手动导出备份。

Electron 的进程隔离、沙箱与有限 IPC 接口参考其[安全说明](https://www.electronjs.org/docs/latest/tutorial/security)和[进程通信文档](https://www.electronjs.org/docs/latest/tutorial/ipc)。
